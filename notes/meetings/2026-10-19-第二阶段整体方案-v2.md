# OpenClaw Skill 移植鸿蒙研究小组后续任务分工方案
**版本**：v1.0
**日期**：2026 年 10 月 19 日
**小组人数**：26 人

---
## 一、研究背景与总体目标
本小组研究课题为 **OpenClaw Skill 向鸿蒙系统移植的方法研究**，采取“传统移植 + SkillVM 创新”双线并行策略。前期已完成环境搭建（OpenClaw 侧 + 鸿蒙 DevEco 侧）、核心论文精读（SkVM、SkCC、SkillSmith、Agent Skills 综述、SkillsBench 等 8 篇）、双侧源码/契约调研（OpenClaw Skill 生命周期源码地图、鸿蒙 Skill 接入契约文档），并在真机上跑通了自定义 Skill 的注册与调用。
根据指导教师意见，下一阶段围绕以下**五项核心目标**展开：
| # | 目标 | 来源 |
|---|---|---|
| G1 | 搞清楚鸿蒙原生智能体机制：用原生小艺智能体调用 Skill，并自建智能体调用原生 Skill 与自定义 Skill | 教师意见第 1、2 条 |
| G2 | 普查 OpenClaw 生态现有 Skill，按可移植性分级（直接可移植 / 修改后可移植 / 困难不可移植），每级产出样例 | 教师意见第 3 条 |
| G3 | 验证 Skill 运行时形态：是否必须转换为 ArkTS（ets）代码，其他形态可否运行，及性能表现 | 教师意见第 4 条 |
| G4 | 评估 SkillVM 路线（含 AOT/JIT 跑前跑后优化）对现有 Skill 的覆盖能力 | 教师意见第 5 条 |
| G5 | 建设公开 GitHub 仓库，将移植完成的 Skill 开源，支持他人一键导入使用 | 教师意见第 6 条 |

## 三、各小组任务书
### 甲组：鸿蒙原生机制组（9 人）
**任务目标**：产出一套完整的《鸿蒙智能体与 Skill 机制实验报告》，回答“鸿蒙原生机制如何运作、Skill 以何种形态运行、性能代价几何”。
**内部分工**：
| 小队 | 人数 | 任务 | 交付物 |
|---|---|---|---|
| 甲-1 智能体链路队 | 3 | ① 真机验证小艺（系统智能体）调用官方原生 Skill 的完整链路；② 同一链路下调用自定义 Skill；③ 基于 AgentExtensionAbility 自建智能体，验证“智能体 → 意图匹配 → Skill → Ability”调度关系 | 调用链路实验记录（含录屏）+ 自建智能体 Demo 工程 |
| 甲-2 接入方式对比队 | 3 | 对比 Agent / Skill / A2A 三种接入方式的适用场景、调用方式、能力边界 | 三种接入方式对比分析文档 |
| 甲-3 运行时与性能队 | 3 | ① 基线实验：纯 ArkTS 入口脚本；② 形态实验：Skill 内经 WebView 加载 JS 逻辑，验证非 ArkTS 形态可行性；③ 性能测量：两种形态下的启动延迟、内存占用、执行耗时对比 | 运行时形态可行性结论 + 性能数据表（含测试方法说明） |
**资源需求**：真机（需手动签名，组内共享排期）；性能实验需把关 benchmark 设计，保证数据可信。
**里程碑**：
- 第 1 周：甲-1 完成原生链路与自建智能体验证；甲-2 完成对比表初稿
- 第 2 周：甲-3 完成两种形态实验与性能数据；全组合稿《机制实验报告 v1.0》
### 乙组：Skill 普查与移植组（9 人）
**任务目标**：产出一套《OpenClaw Skill 可移植性普查分类表》，并在每个可移植性级别产出完整移植样例，形成《Skill 移植手册》。
**内部分工**：
| 小队 | 人数 | 任务 | 交付物 |
|---|---|---|---|
| 乙-1 普查队 | 3 | 爬取/整理 OpenClaw 生态（bundled skills + ClawHub）全量 Skill 清单，登记名称、来源、类型、脚本语言、系统依赖、宿主能力依赖等字段 | Skill 全量普查表 v1 |
| 乙-2 移植样例队 | 4 | 按 L1/L2 分级各移植 3 个样例（L1：纯描述型，改写 description/frontmatter 即可；L2：含通用脚本，翻译为 ArkTS 入口脚本）；每个样例保留 OpenClaw 原文件与鸿蒙版的完整对照 | 6 个可运行移植样例 + 移植手册 |
| 乙-3 困难分析队 | 2 | 挑选 2~3 个 L3 困难 Skill（强依赖 bash/python 生态、MCP 工具链或 OpenClaw Router 特有调度），逐个分析卡点：缺什么运行时、缺什么工具协议、理论上如何补齐 | L3 卡点分析报告（与丙组论文结论互证） |
**工作接口**：
- 移植样例（L1/L2）完成后 → 以 PR 形式提交至skill开源仓库
- L3 卡点分析结论 → 同步给丙-1 评估队，作为 SkillVM 覆盖率评估的输入
- A1 调任同学负责在 OpenClaw 原平台逐个验证 Skill 行为，作为移植正确性的对照基线
  **里程碑**：
- 第 1 周：普查表 v1 完成；L1 样例移植启动
- 第 2 周：L1 样例 3 个入库；L2 样例启动；L3 卡点分析初稿
### 丙组：SkillVM 评估与开源组（8 人）
**任务目标**：其一，评估 SkillVM 路线对现有 Skill 的覆盖能力（定位为“评估与原型验证”，非从零造 VM）；其二，建设并运营对外的开源仓库。
**内部分工**：
| 小队 | 人数 | 任务 | 交付物 |
|---|---|---|---|
| 丙-1 评估队 | 4 | ① 深挖 SkVM / SkCC / SkillSmith 中“跑前优化（AOT：静态编译、类型检查、安全分析）+ 跑后优化（JIT：运行时反馈、缓存）”机制，形成技术选型对比表；② 用乙组样本（L1/L2/L3 各若干）逐级测试 SkillVM 路线的承载能力 | 技术机制对比表 + 《SkillVM 覆盖率评估报告 v1.0》 |
| 丙-2 开源仓库队 | 3 | 建设 `openclaw-skills-for-harmony` 仓库：每个移植 Skill 一个目录（SKILL.md + ArkTS 脚本 + 演示录屏 + 来源标注）；提供一键导入脚本；撰写 README 与贡献指南；确定开源协议（建议 MIT） | 上线仓库 + 首批 5 个 Skill（L1×3 + L2×2）入库 |
| 丙-3 IR 草案队 | 1~2 | 基于乙组语义映射表与 L3 问题清单，起草 SkillIR 规范（注意与鸿蒙特有字段解耦，通过绑定/投影机制适配目标运行时） | SkillIR 规范草案 |
**开源仓库验收标准**：外部开发者 clone 仓库后，按 README 三步以内即可将任一 Skill 导入自己的鸿蒙工程并成功调用（导入脚本示例：`npm run import -- --skill=<name>`）。
**里程碑**：
- 第 1 周：仓库骨架上线（含 README + 首个 Skill）；机制对比表完成
- 第 2 周：评估报告 v1 + 首批 5 个 Skill 全部入库
## 四、跨组协作接口
三组产出必须互相咬合，由大组负责人在每周例会上对齐：
| 输出方 | → 输入方 | 内容 |
|---|---|---|
| 乙组普查表 + L3 卡点分析 | 丙-1 评估队 | 评估样本与问题清单 |
| 乙组移植样例 | 丙-2 开源仓库队 | 以 PR 形式入库 |
| 甲组性能数据 | 丙-1 评估队 | 并入评估报告的性能章节 |
| 丙组论文结论 | 乙-3 困难分析队 | 移植障碍分类的理论依据 |
| 丙组开源仓库 | 全员 | 移植成果的最终归宿 |
## 五、时间计划（以两周为一迭代）
| 阶段 | 时间 | 关键节点 |
|---|---|---|
| 迭代一 | 第 1~2 周 | 机制实验报告 v1 / 普查表 v1 / 6 个样例 / 开源仓库上线 |
| 迭代二 | 第 3~4 周 | 评估报告 v1 / L2 样例扩容 / 移植手册 v1 / SkillIR 草案 |
| 迭代三 | 第 5~6 周 | 端到端对比实验（手工移植 vs SkillVM 生成）/ 仓库二期 Skill 入库 |
| 迭代四 | 第 7~8 周 | 整体成果整理：研究总结报告 + 开源仓库正式发布 + 对外分享 |
每迭代结束（即每两周）向指导教师汇报一次，形式为三组各 10 分钟汇报 + 大组 5 分钟总结。

| 真机测试 | 至少 2 台支持 HarmonyOS 7 的真机（Agent Framework Kit 不支持模拟器） | 组内征集 + 申请实验室设备；建立共享排期表 |
