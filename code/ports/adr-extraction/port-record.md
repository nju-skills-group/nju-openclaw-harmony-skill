源正文也允许记录较弱的推断。本子集把未能确认采纳的内容集中到 `open_items`，方便核验已定与待定的区别。当前实现根据源功能重新编写。 [ClawHub 源正文和许可](https://clawhub.ai/anderskev/skills/adr-decision-extraction)

## 用例 A 重复决定和待定提案

输入下面的合成纪要。给原版、默认 Work、Write Adr 和移植包使用同一份输入。

```text
09:00 甲：这轮在哪个入口验收？备选是小艺 Work 云电脑和鸿蒙应用 Skill。
09:03 乙：现在 Work 云电脑可以安装并调用独立包，应用侧测试入口尚未就绪。
09:05 甲：[ADR] 本轮统一用小艺 Work 云电脑验收，因为它目前能安装并调用独立包。
09:07 乙：确认一下，大家这一轮都在 Work 云电脑验收。
09:10 甲：下轮是否改用鸿蒙应用 Skill，等测试入口确认后再决定。
```

预期 `decisions` 恰好一条，`chosen_option` 是小艺 Work 云电脑，`confidence` 为 `high`。`source_context` 包含输入中的原文确认句，09:07 的重复表述没有产生第二条决定。`open_items` 包含下轮是否改用鸿蒙应用 Skill。字段措辞可以变化，状态与证据需要和原文一致。

普通模式的参考输出如下。v0.1.2 预期显示为单个 JSON 代码块，复制其内部内容后应能直接解析。请只把上面的纪要发给 Work。

```json
{
  "decisions": [
    {
      "title": "确定本轮验收入口",
      "problem": "这轮在哪个入口验收？",
      "chosen_option": "小艺 Work 云电脑",
      "alternatives_discussed": ["鸿蒙应用 Skill"],
      "drivers": ["Work 云电脑目前能安装并调用独立包"],
      "confidence": "high",
      "source_context": "本轮统一用小艺 Work 云电脑验收，因为它目前能安装并调用独立包。"
    }
  ],
  "open_items": [
    {
      "topic": "下轮是否改用鸿蒙应用 Skill",
      "source_context": "下轮是否改用鸿蒙应用 Skill，等测试入口确认后再决定。"
    }
  ]
}
```

## 用例 B 只有待定提案

```text
10:00 甲：可以考虑把周会改到周五。
10:02 乙：等大家确认空闲时间后再决定。
```

预期 `decisions` 为空，`open_items` 含周会时间提案，并引用仍待确认的原文。两种工作方式都要返回可解析 JSON。

## 用例 C 缺参和加载对照

只发送「请使用 `adr-extraction` 提取决策」，不给讨论材料。预期 JSON 代码块内返回 `missing_transcript`。历史试验包 v0.1.2 使用 `group-b-adr-decision-extraction` 作为标识，包验证模式的预期标记为 `GB-ADR-8A8C134A59517800`。上架包的调用证据可使用平台可见的 Skill 调用记录。

### 用例 A 首轮 Work 输出

[实际 JSON](evidence/work/case-a-validation-v0.1.0.json)由组长贴回。归档时去除聊天复制产生的 HTML 空格实体和换行转义，字段值按贴回内容保留。当前可见证据为回复文本，安装日志、加载事件、实际会话与停用对照待补。

| 验收点 | 结果 |
| --- | --- |
| JSON 可解析，验证标记匹配 | 通过，结果含与包内相同的 `skill_probe` |
| 决策计数、去重与待定判别 | 通过。输出一项本轮 Work 云电脑验收决定，以及一项下轮是否改用应用 Skill 的待定事项 |
| 逐字证据 | 部分通过。待定事项证据与原文一致。已定决策的证据拼接了 09:05 和 09:07 两行并省略中间换行，整段无法按原文连续子串精确匹配 |

结论为「v0.1.0 验证标记 `GB-ADR-228DD4E8CF3B704A` 命中，业务提取通过，原文证据部分通过」。
