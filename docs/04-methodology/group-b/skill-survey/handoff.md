## L2 首批建议

1. `weather`：以城市作为输入，通过目标平台网络 API 请求天气 JSON，提取天气／温度／风速等输出。测试成功、城市无效、超时和响应字段缺失。不得只用硬编码天气结果验收。
2. `trello`：先做已授权测试看板的只读列表查询，再扩展写操作。对照请求参数、分页、JSON 和授权失败。真实账号认证由测试人员配置，报告不保存 token。
3. `meme-maker`：模板筛选和本地 SVG 生成是清晰起点；保留输入文本、输出文件与模板规则。若只实现本地分支，必须标“部分功能”，不能把 Imgflip 远程分支同时勾为通过。

备选为 `goplaces`、`notion`、`openai-whisper-api`。它们是静态 L2 候选，需要账号或服务条件；本次未使用 API key、未产生模型费用。

## 给丙组的三个 L3 样本

### tmux：执行环境缺口

证据：frontmatter 明确 darwin/linux 与 `tmux`；目录含 `find-sessions.sh`、`wait-for-text.sh`。业务依赖持久终端、输入注入、屏幕缓冲和会话状态。

需补齐：PTY／shell 服务、会话生命周期与授权协议。远程 Linux 可作为一种架构，但应报告远程执行比例、网络开销和失联行为。仅将 bash 语法翻译为 ArkTS 不会获得终端服务。VM 评估应拆开“控制逻辑可表达”与“PTY 宿主能力已提供”。

### mcporter：协议与进程缺口

证据：frontmatter 依赖 `mcporter`；正文同时包含 HTTP MCP 与 `--stdio` 启动命令，还涉及 OAuth 和工具生成。

需补齐：HTTP／SSE 等实际传输适配、工具发现和 schema、凭据、超时、错误传播。stdio 路线另需 Node/Bun 等服务端进程。先测试远程 HTTP 工具，再测 stdio，不能用前者证明后者可用。

### peekaboo：平台专用能力缺口

证据：darwin 门控、`peekaboo` CLI、macOS 应用 Bridge 和屏幕／辅助功能权限。

需补齐：鸿蒙目标应用界面读取、定位、输入、权限及动作后验证。VM 能处理控制流程不等于拥有系统 UI 自动化能力；远程 macOS 方案亦不能算鸿蒙本机原生移植。

## 运行记录模板

每个真正移植的 Skill 使用仓库现有 skill-port-template.md，并补以下字段：

| 字段 | 填写内容 |
|---|---|
| 原始身份 | owner/slug 或内置目录、版本／commit、源码哈希 |
| 功能范围 | 完整、子集、远程宿主；删减点逐项列出 |
| 原平台基线 | OpenClaw 版本、模型、输入、真实调用轨迹、输出 |
| 鸿蒙环境 | 设备／系统／SDK、入口／注册配置、权限 |
| 正常与失败用例 | 同一输入下两端结果、错误处理、差异解释 |
| 性能 | 计时边界、冷／热启动、重复次数、内存指标；缺数据写未测 |
| 交付证据 | 工程路径、来源许可、日志与录屏；评审人 |

普查表由乙组维护。甲组提供注册、网络／文件／工具桥接的实际可用性；丙组使用 L3 缺口做 VM 能力覆盖实验。等待甲组确认前，不臆造 skillProfiles 或 ArkTS 入口字段。
