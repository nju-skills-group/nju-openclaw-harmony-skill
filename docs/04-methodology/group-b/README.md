# 乙组 Skill 分类与移植

乙组研究 OpenClaw Skill 的功能、执行依赖及向鸿蒙迁移的方法。本目录汇总普查与复核、原平台基线、Harness 源码分析和移植进展。实际移植工程统一放在仓库 `code/ports/` 下。

当前工作是：每人认领 L1、L2 各一个案例开展实际移植，并结合案例理解 OpenClaw 如何发现、加载 Skill、执行工具和返回结果。实现进度与运行验收分别记录，设备或接口尚不可用时如实说明。

## 已有成果与使用边界

原始普查固定于2026年10月25日的材料范围：50项官方 bundled Skill，以及按8类依赖形态选出的24项 ClawHub 社区样本，共74条来源与版本记录。社区样本是目的性选样；不同来源的同名 Skill 分别保留，不能将74条记录解释为74种独立功能。

上一轮 S1、S2 沿用这74项，分别重点复核5项。新表没有新增样本，也没有改变原有基础 L1/L2/L3 等级，主要补充依赖细节、证据位置和复核状态。后续将有效修改合入原有数据源，不另维护平行普查表。

S3在既有标准上细化“待确认”、适配路径和判定流程，并吸收部分运行结果。E组提交涉及6个实际测试样本，覆盖提示执行、网络服务、脚本和宿主工具；功能范围与证据完整度不同，不能合称6个完整 Skill 全部通过。

上述材料尚不构成鸿蒙移植成功证明。具体结论请查看各案例的功能范围、实际输入输出与目标端证据。

## 怎样阅读一个案例

按照“原始样本与静态依据 → 原平台输入输出 → Harness及工具依赖 → 适配实现 → 目标端结果”阅读。

- **weather：**S1重点复核 → E2原平台正常、备用及超时记录 → S3候选L2结论。适合观察网络工具如何映射为目标能力。
- **healthcheck：**S1重点复核 → E4三条只读命令及后台任务记录。该实验尚未纳入上一轮S3提交版，汇总时应补充。
- **ontology：**脚本级Project—Task关系流程与Agent创建Note流程分别记录，不合并成同一功能的完整成功。

## 更新原则

1. 保留 `skill-survey/` 及既有相对路径，优先增量修改，不为整理外观搬动全部材料。
2. 普查数据按现有生成流程维护；先修改对应判读输入，再生成CSV、JSON、Markdown和Excel，不分别手动维护多个冲突版本。
3. 新运行保留独立证据。后续成功不覆盖历史失败；摘要可以更新，但须注明依据。
4. 每次阶段汇总只写新增变化、成果位置和未完成项，不复制整套旧成果。
5. 文档与工程改动使用功能分支，按仓库规范经PR审阅后合并。一次整理可以集中为一个PR，无须每个文件单独提交。

本入口在相关成果合并后更新。工作中的内容可链接PR并标注待审阅；不要只写“已完成”却没有对应文件或证据。
