## 3. 四类评价内容与状态

一次判定绑定：sample_id + 源版本 + scope_id + 适配版本 + 工具链版本 + 模型/harness + 设备环境 + 协议版本。完整原功能、子集、替代实现必须明确；运行位置另记 native、remote 或 hybrid。远程执行通过不计入本机原生覆盖。

对应原评估报告第 3 节的四类内容，本文统一称为：静态验证、工具链验证、原平台基线、目标运行。其中“静态验证”对应原报告的“机制可表达性”，包括源码、依赖和适配方案分析，不代表已执行成功。它们不是相互独立的评分轴，不计算四类总分。行为一致性纳入两端用例对照，覆盖率口径和性能数据按第 5 节记录，不另设第五类。

每类统一填“通过 / 部分通过 / 失败 / 未测 / 阻断”（机器记录依次对应 pass / partial / fail / untested / blocked）。全部约定门槛有证据满足才填通过；已满足部分门槛但仍有失败或缺项填部分通过，并列明缺项；已尝试但没有满足门槛填失败；未开展填未测；因明确缺前置条件而无法开展填阻断。失败重试保留全部历史，不以最后成功覆盖先前失败。

| 评价类别 | 通过门槛 | 不能推导的结论 |
| --- | --- | --- |
| 静态验证 | 原包复核完成；功能、依赖、权限及副作用有 IR/适配映射和依据，关键缺口已核查 | 不证明工具或目标运行成功；C-3 未定稿时只能称适配分析 |
| 工具链验证 | 真实使用 SkVM 等工具处理固定输入，保留版本、命令、目标 harness、输出或错误；完成执行前约定的处理与检查，说明意义和限制 | 不只限于生成文件；检查随工具真实能力确定。退出码 0 或生成代码本身不证明鸿蒙支持 |
| 原平台基线 | 固定原包在 OpenClaw 实际加载/使用，约定用例满足原平台断言，输入、输出及调用轨迹可检查 | 原平台成功不证明目标成功；原版失败也须保留，不把它作为目标正确的依据 |
| 目标运行 | 声明入口被实际调用，输入、业务操作及回包可追踪；约定目标用例满足功能、错误处理和副作用断言，记录设备及权限 | 构建成功、应用启动或直接调用业务函数不等于系统 Skill 调用；缺原平台对照时不能宣称行为一致 |

目标运行还须填入口类型：系统 Skill / App 内部 / 自建 Agent / 远程；分别统计，不合成“系统调用成功”。四类工作可以分别推进；工具链自带运行验证时可引用相同证据，但需说明工具处理与目标任务各支持什么结论。

声明“某 scope 在鸿蒙覆盖”要求目标运行通过、原平台对照可用、同输入两端必需断言全部满足，正常/失败分支及副作用符合约定，并解释动态数据差异。行为一致性以逐例对照记录支撑，不另设独立状态；字符串相同或模型自评不能独立证明正确。运行位置与范围须明确。声明“SkillVM 路线覆盖”还须工具链验证通过且目标使用的产物可溯源到该工具链。人工修改保存 diff，标为“工具链＋人工适配”。完整本机覆盖另外要求全部主要功能无未测必需分支且为 native。本机调用云 API 不自动算远程宿主；remote 指将技能宿主流程/进程委派给外部机器。

## 4. 用例、对照和重复规则

27 个基础用例主要验证“目标运行”，检查移植后 Skill 在鸿蒙上的功能、异常处理和必要操作；用例通过率等是目标运行指标。同样用例在 OpenClaw 上执行形成“原平台基线”，用于逐例比较移植效果。静态验证由原包及能力映射分析支撑，工具链验证由实际适配工具实验支撑，二者均不能直接按这 27 个用例的通过率判定。

每例先写预期、判定人/程序和证据，再运行。结构化输出用字段/schema 断言；文件检查可解析性及内容；有状态操作检查前后状态；自然语言用逐项 rubric，不要求措辞相同。人工评分由执行人初判、另一成员复核，分歧保持待裁决。

核心对照是原 OpenClaw 和目标同输入。尽量固定模型版本、采样参数、工具预算及任务初态；不能固定的变量单列，不能将跨模型差异全归因于适配。实时天气用同服务/城市/时间窗及保存响应比较字段转换，禁止要求不同时刻数值绝对相等。

27 个编号是基础用例的统计单位。一例含多个子场景时，执行前补子编号（如 S04-03a/b）；每个子场景分别重复和留证，全部必需子场景通过才计该基础用例通过。平台专用、不适用项保留编号并说明原因，不默默缩小分母；新增或调整用例须提前固定集合及版本。

每例每条可用路径默认独立运行 3 次，每次复位状态；全部必需断言在 3 次均满足才把该例标为通过。少于 3 次仅为试跑。3 次只是小规模验证，不足以宣称稳定可靠。模型失败、重试、人工干预均计入记录。正常用例执行成功与故障注入被正确处理分别计数。

故障注入、固定响应、mock 服务用于测试适配器和错误处理；单独标 fixture，不可替代 live 网络/真实平台证据。无 Skill、原始未适配、人工适配、自动适配四组可作为扩展对照，资源不足时明确未测；核心两端对照不可用模型自评替代。

## 5. 指标与分母

固定 N=9，各等级 N_L=3。每类评价内容按固定环境、入口、适配路线及预先声明的测试范围统计，五种状态之和等于 N；该表未开展的样本也须列为未测或阻断。每个 Skill 在同一张统计表只能有一个状态：多个必需 scope 全部通过才算通过，有部分满足但有失败或缺项则算部分通过。不同环境/路线分别制表，不把某个成功子集当作整个 Skill 成功。

| 指标 | 计算与报告规则 |
| --- | --- |
| 工具链处理覆盖 | 工具链验证通过的唯一 Skill 数 / 9；scope、处理任务及检查范围同时列出 |
| 完整本机覆盖 | 满足完整本机门槛的唯一 Skill 数 / 9；SkillVM 路线另要求工具链验证通过及产物溯源 |
| 子集/远程结果 | 分别报 scope 数、涉及唯一 Skill 数和 scope 清单；不加进完整覆盖分子 |
| 执行进度 | 有实际运行记录的样本数 / 9；blocked、untested 单列 |
| 已测通过率 | 通过数 /（通过数＋部分通过数＋失败数），四类分别统计，展示未测/阻断数；分母为 0 写 N/A |
| 用例覆盖与通过 | 两端分别统计：完成全部必需子场景及约定重复次数的用例数 / 预注册用例数；通过用例数 / 预注册用例数。仅部分执行的用例单列；另报逐次通过次数 / 实际运行次数 |
| 调用质量 | 自然语言选中率、参数合法率、调用完成率、任务成功率分别统计并写明各自适用请求集合；强制指定 Skill 的测试不测召回 |

全部未测时报告“实测覆盖未知”，可以报已有通过证据 0/9，但不可解释为真实可移植率为 0。失败原因分为源样本问题、模型行为、工具链、目标能力/协议、权限/认证、外部服务、测试环境和未知；允许多标签，主因需要日志支持。

性能记录：端到端从提交输入至最终结果；工具执行从适配器收到参数至回包；编译/AOT 成本单独计时。功能通过后，默认冷启动（重启应用/会话，记录清除内容）3 次，热运行（预热1次不计）10 次，报告样本数、中位数、最小/最大值与原始值，不用这些小样本宣称尾延迟。可得时记录输入/输出 token、工具次数和峰值内存及测量工具。未知值不是 0。远程路线分列网络时间及执行位置。v1 不设跨所有 Skill 通用延迟上限；比较必须注明模型、设备、服务与计时边界，无法匹配时只作描述。

## 6. 证据与依赖

证据按四类归档；记录模板各节及汇总中的证据栏填写附件链接。

| 类别 | 至少保留什么 |
| --- | --- |
| 静态验证 | 固定版本源码及证据位置、能力映射、依赖和缺口说明 |
| 工具链验证 | 工具版本、输入、命令、目标配置、输出或报错、处理结果检查 |
| 原平台基线 | OpenClaw 和模型配置、用例输入、调用轨迹、实际输出及逐项判定 |
| 目标运行 | 目标工程和设备环境、入口及权限、实际调用与回包、用例输出及逐项判定 |

两端对照附在目标运行记录中，链接对应原平台用例并说明差异；性能数据附原始值、测量方法及来源，不另设评价类别。所有证据关联 Skill/版本、用例或工具处理批次、时间、执行人和复核人；不保存密钥。

| 依赖方 | 需交接 | 缺失时可继续什么 |
| --- | --- | --- |
| 乙组 | 固定原包/逐文件清单、原平台用例轨迹、实际移植工程与功能范围 | 静态资料分析及工具链试跑；原平台基线标未测或阻断，缺对照不宣称行为一致 |
| 甲组 | 验证过的入口/设备/SDK、网络文件桥接、权限及回包记录、性能数据 | 静态验证和工具链验证；目标运行、两端对照和性能不补造数据 |

| C-1/C-3 | 经核对的机制依据、IR 字段/目标绑定版本 | 暂用自然语言映射，不声称已有正式 IR 支持 |
