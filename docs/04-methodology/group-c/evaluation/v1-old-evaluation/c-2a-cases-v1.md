# C-2A 目标运行基础用例 v1

与 [方法协议](c-2a-method-v1.md) 配套，共 27 个预定义用例；全部未执行。每例默认每路径 3 次。表内文本为固定测试输入；具体 schema、原生工具参数及原技能功能边界须在固定原包复核后写入模板第1节用例计划，不将本文设计的判据冒充原作者声明。

## 用例归属与用途

这 27 个用例主要用于“目标运行”：在鸿蒙上执行，检查移植后的 Skill 功能、异常处理及必要操作是否正确，据此统计用例通过率等指标。用例是测试内容，通过率等才是实验指标。

同样用例在 OpenClaw 上执行，形成“原平台基线”；两端结果逐例对照，用于判断移植效果和行为一致性。两端执行状态分别记录，缺少基线时保留缺项。

“静态验证”另外依据原包和能力映射分析；“工具链验证”另外记录实际使用 SkVM 等工具进行适配的过程及结果。不能用这 27 个用例的通过率直接替代这两类判断。工具链自带执行测试时，可引用用例结果，但需注明运行平台及证据用途。

以下是范围明确的最小测试集，不足以独立认定完整 Skill 覆盖。新增完整功能用例需执行前冻结；不适用须说明源码依据，不得直接从固定集合删除。

每个编号计一个基础用例；含多个子场景时补 a/b 等子编号，每个子场景分别重复、留证，全部通过才计该基础用例通过。两端分别统计完成数、通过数、部分执行数及计划数，不适用项保留并说明原因。

## 运行前冻结的夹具

- 测试服务脚本/版本与响应文件、schema、模板资源、测试应用工程：各保存路径和哈希。表内 mock 场景不视作真实第三方服务已兼容。
- T_timeout、重试上限与计时容差：由 C-2B 按实际接口预注册；未填写不得跑超时判定。所有路径保持相同预算或解释差异。
- L1：从原包核定字段、五阶段名称与引用资源，把要求转成逐项布尔评分表；执行人初判、另一成员复核，保留意见与分歧。
- L3：没有 PTY/MCP/UI 环境时记“阻断”和缺口；控制逻辑可表达不能替代执行记录。peekaboo 目标应用替换属于替代实现，不能声称保留 macOS 原应用集成。
- 在模板第2节能力映射表注明各功能对应的 scope 和用例编号。未覆盖的功能保留未知；meme-maker 远程分支、trello 写操作等须另加用例才能声明对应范围覆盖。
