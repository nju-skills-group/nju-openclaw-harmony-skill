## 五、最终验收与跨组接口

1. **工作包完成 ≠ 最终成果完成**。最终成果协调人与所有参与者一起，对照第一节完成整体审查，检查各部分口径、链接、证据和限制，并在 [`README.md`](README.md) 更新最终状态。只有完整成果满足验收条件，才能标为“已验收”。
2. 阶段性工作包可以独立通过 PR 合并到 `main`，注明“阶段成果 / 未完成最终验收”。PR 至少一位其他成员审阅，遵循 [全仓库工作流](../../05-protocols/git-workflow.md)，不另设长期 `group-c` 分支。
3. **乙 → 丙**：普查表与 L3 卡点、语义映射及逐个移植的 Skill 工程/原平台对照；**甲 → 丙**：目标运行契约与性能测量；**丙 → 乙**：可追溯的机制/障碍分类结论。缺少输入时标记具体依赖和未测范围，不补造数据。
4. **【发布仓库】**正式 Skill 需原始来源和许可证、`SKILL.md`、ArkTS 脚本、演示录屏、可核对的构建/调用和功能证据。发布仓库整体按原任务书的三步以内导入成功调用验收；不把文件复制或合成夹具等同于鸿蒙实际调用。
5. 建议成果协调人在成果最终 PR/验收记录中注明：参与的工作包及 PR、全部审阅成员、统一结论、未解决问题、满足/未满足的各条验收条件。未通过可以合并明确标为研究草稿的内容，但不能把成果标为已完成。
