# 丙组第二阶段计划与验收（认领版）

> 对应 2026-10-19《Skill 移植后续任务分工方案》中的「丙组：SkillVM 评估与开源组」。计划 8 人，目前实际 7 人。**待组员讨论确认后认领。**
>
> 丙组定位为 **SkillVM 路线评估与原型验证（非从零实现 VM）＋对外 Skill 发布仓库维护**。日常研究与实验在本研究仓库完成；`openclaw-skills-for-harmony` 是面向外部用户的正式 Skill 发布仓库。

## 二、参考工作包（共 6 个；可合并、调整、多人认领）

> **工作包不是正式成果，也不按七人强制一人一包。** C-1 与 C-3 耦合紧密，建议不再拆；C-2 和 C-4 有相对独立、且分别受跨组依赖影响的环节，建议各分两包。分工仅供认领时参考，讨论确认后可调整，但最终仍以第一节四项成果验收。

| 参考包 | 对应成果 | 该包可独立推进的环节 / 中间产出 | 需要同成果成员共同完成的事情 | 建议启动时机 |

| **C-2A** | 覆盖率评估报告 | 选取/固定乙组 L1/L2/L3 代表样本；定义“支持/覆盖/未测”的含义、指标、对照和记录方法 | 与 C-2B 对齐可测指标，最终共同审查和完成**整份评估报告** | 立即，乙组现有普查可用 |

- `code/skill-vm/` **不是第七个工作包**。只有 C-2B 的真实工具链实验产生可复用的脚本或测试时，才在该目录保存；实验方法、结果和结论仍统一归入 C-2 报告。
- 论文笔记、安全/许可、性能数据、CI 等不是额外的独立正式成果：它们分别服务 C-1/C-2/C-3 或 C-4 的验收，不另造任务包。
- C-2A 和 C-2B 可以分别提交阶段性 PR；建议先合并共用评价口径，再逐次补实测内容。**必须共同整合进 `evaluation/coverage-evaluation-v1.md`，才能申请 C-2 的最终验收。**

## 五、最终验收与跨组接口

1. **工作包完成 ≠ 最终成果完成**。最终成果协调人与所有参与者一起，对照第一节完成整体审查，检查各部分口径、链接、证据和限制，并在 [`README.md`](README.md) 更新最终状态。只有完整成果满足验收条件，才能标为“已验收”。
2. 阶段性工作包可以独立通过 PR 合并到 `main`，注明“阶段成果 / 未完成最终验收”。PR 至少一位其他成员审阅，遵循 [全仓库工作流](../../05-protocols/git-workflow.md)，不另设长期 `group-c` 分支。
3. **乙 → 丙**：普查表与 L3 卡点、语义映射及逐个移植的 Skill 工程/原平台对照；**甲 → 丙**：目标运行契约与性能测量；**丙 → 乙**：可追溯的机制/障碍分类结论。缺少输入时标记具体依赖和未测范围，不补造数据。
4. **【发布仓库】**正式 Skill 需原始来源和许可证、`SKILL.md`、ArkTS 脚本、演示录屏、可核对的构建/调用和功能证据。发布仓库整体按原任务书的三步以内导入成功调用验收；不把文件复制或合成夹具等同于鸿蒙实际调用。
5. 建议成果协调人在成果最终 PR/验收记录中注明：参与的工作包及 PR、全部审阅成员、统一结论、未解决问题、满足/未满足的各条验收条件。未通过可以合并明确标为研究草稿的内容，但不能把成果标为已完成。
